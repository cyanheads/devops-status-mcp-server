# 0.8.3 — 2026-09-24

## Added

- **`nextToolSuggestions`** on `devops_status_check` and `devops_watch_stack` ([#47](https://github.com/cyanheads/devops-status-mcp-server/issues/47)) — one pre-filled `devops_suggest_action` call per vendor whose indicator is `minor`/`major`/`critical` or that has an open incident of that impact, with `vendor` (registry slug or normalized URL), `vendor_indicator`, `affected_components`, and `incident_summary` filled in. Empty when no checked vendor has a problem; a vendor carrying `error` never qualifies.

## Changed

- README and `docs/design.md` document the fields above; `docs/design.md` corrects `devops_check_certs`'s `invalid_domain` code to `ValidationError`.

## Fixed

- **A domain `devops_check_dns` or `devops_check_certs` could not check reports its failure once, in `error`** ([#45](https://github.com/cyanheads/devops-status-mcp-server/issues/45)) — `flags` stays empty, an SSRF-guard rejection drops the internal `SSRF_BLOCKED: ` prefix, and the DNS output no longer prints an empty resolver header.
- **`devops_check_dns` queries the default resolvers and record types when `resolvers` or `record_types` is an empty array** ([#48](https://github.com/cyanheads/devops-status-mcp-server/issues/48)) instead of returning a clean result after querying nothing. The advertised input schema is unchanged.
- **`devops_check_certs` sets `error` when a TLS handshake completes without a certificate** ([#49](https://github.com/cyanheads/devops-status-mcp-server/issues/49)) — the row keeps `tls` and its session findings in `flags`; every `status: "error"` row now carries a reason.
