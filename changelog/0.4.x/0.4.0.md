# 0.4.0 — 2026-07-02

## Added

- **`src/services/status-adapters/`** — `statusio-adapter.ts`, `slack-adapter.ts`, `aws-adapter.ts`, and `status-dispatch.ts`, which routes each resolved vendor on `api_type` and normalizes its native status API into the existing `StatuspageSummaryResponse` / `StatuspageIncidentsResponse` shapes — every tool works unchanged for non-Statuspage vendors, no schema changes ([#12](https://github.com/cyanheads/devops-status-mcp-server/issues/12)).
- **`aws` and `gitlab` registry entries** — AWS via the public AWS Health Dashboard feed, GitLab via Status.io; registry grows 48 → 50.
- **`VendorApiType`** — `VendorEntry` is now a discriminated union on `api_type: 'statuspage' | 'statusio' | 'slack' | 'aws'`; `statusio` entries carry a `statusio_page_id`. `resolve()` returns a `ResolvedVendor` carrying the `api_type` so the dispatch layer can route; raw-URL passthrough stays Statuspage-only, SSRF guard unchanged.
- **`src/utils/cached-fetch.ts`** — `fetchCached` / `fetchJsonCached` extracted from the Statuspage service; adapters share the same TTL cache and honor `DEVOPS_STATUS_CACHE_TTL_MS` / `DEVOPS_STATUS_FETCH_TIMEOUT_MS`.
- **`bun run verify:registry`** (`scripts/verify-registry.ts`) — probes every registry entry through the same dispatch path the tools use and exits non-zero on drift. Standalone by design (hits ~50 live endpoints; devcheck stays offline).
- **Adapter tests** — `tests/services/status-adapters/` with fixtures captured from the live endpoints (Slack current/history, GitLab's Status.io page, raw UTF-16BE AWS bytes), plus dispatch regression tests pinning Statuspage vendors to the unchanged `/api/v2/*` paths and a registry-integrity suite (50 unique slugs, https-only URLs, Status.io page IDs).

## Changed

- **AWS feed semantics** — the AWS Health feed is one global list of currently-open events, UTF-16 encoded (BOM-sniffed decode, observed live as UTF-16BE), with no history feed: `filter: "resolved"` and `filter: "scheduled"` are always empty for `aws`. Severity codes are empirical (`'0'` → none, `'1'` → minor, `'2'`/`'3'` → major); `critical` is never emitted since every feed event is region/service-scoped.
- **Tool and resource `.describe()` prose** — backend-neutral wording ("vendor's status API" instead of "Statuspage") and 50-vendor counts across `devops_status_check`, `devops_get_incidents`, `devops_watch_stack`, `devops_list_vendors`, the vendor resource, server instructions, and README.

## Fixed

- **`auth0`** — URL swapped from the dead `http://status.auth0.com` to the live `https://auth0.statuspage.io` Statuspage ([#11](https://github.com/cyanheads/devops-status-mcp-server/issues/11)).
- **`slack`** — was a broken Statuspage entry (the `/api/v2/*.json` paths 404); now served by the Slack status API adapter (`/api/v2.0.0/current` + `/history`, severity derived from incident `type` since the schema carries no impact field) ([#11](https://github.com/cyanheads/devops-status-mcp-server/issues/11)).
- **`neon`** — was pointed at the defunct `status.neon.tech`; now served through the Status.io adapter against `neonstatus.com` ([#11](https://github.com/cyanheads/devops-status-mcp-server/issues/11)).
