# 0.5.5 — 2026-07-30

## Changed

- **`@cyanheads/mcp-ts-core`** bumped `^0.10.14` → `^0.11.0`; `bundle` now also strips platform-specific native bindings (`@duckdb/node-bindings-*`) from a packed `.mcpb`, since this framework version's `.mcpbignore` cannot reach them and a native binding would otherwise lock the bundle to the platform it was packed on.
- **Statuspage response shape** is now validated against Zod schemas before a payload is cached or returned, so a 200 response carrying some other service's JSON is rejected rather than dereferenced downstream ([#32](https://github.com/cyanheads/devops-status-mcp-server/issues/32)).
- **`devops_status_check`** no longer declares a `statuspage_unavailable` error contract — every vendor is fetched under `Promise.allSettled`, so a fetch failure can never reach a top-level throw; it now reports only in the per-vendor `error` field ([#32](https://github.com/cyanheads/devops-status-mcp-server/issues/32)).
- **`devops_check_dns`** resolver input documents the accepted `ip:port` / `[ipv6]:port` forms and rejects hostnames outright.
- Statuspage's `impact` enum gained `maintenance`, since scheduled-maintenance windows are folded into incident history on some pages; the status-adapter severity rollups (AWS, FireHydrant, Slack) exclude it from ranking.

## Fixed

- **`devops_get_incidents`** tolerates a 404 on the scheduled-maintenances endpoint under `filter: "all"` (some pages publish no maintenance feed at all), while still surfacing the 404 as `statuspage_unavailable` under `filter: "scheduled"`.
- **Sparse Statuspage payloads** — pages that omit `incidents`/`scheduled_maintenances`/`description` entirely rather than sending `[]`/`null` no longer throw a raw `TypeError` downstream.

## Security

- **Unspecified addresses and `ip:port` resolvers bypassed the private-target guard** — `0.0.0.0/8` and the bare IPv6 unspecified address (`::`) had no entry in the SSRF range tables, and a `127.0.0.1:53`-style resolver read as an unmatched IPv6 literal instead of a loopback IPv4 address with a port. `checkIp()` now strips an optional port suffix before dispatch, both unspecified forms are blocked, and `assertSafeResolverIp()` rejects any input that isn't a valid IPv4/IPv6 literal instead of passing it through to `dns.setServers()` ([#29](https://github.com/cyanheads/devops-status-mcp-server/issues/29)).
- **Redirects were followed without re-checking the SSRF guard** — `assertSafeUrl()` validated only the caller-supplied hostname; a public URL that 3xx-redirected to a private, loopback, or cloud-metadata address was fetched and its body returned to the caller. `fetchCached()` now sets `redirect: 'manual'` and re-runs `assertSafeUrl()` on every `Location` header before following it, capped at 5 hops ([#30](https://github.com/cyanheads/devops-status-mcp-server/issues/30)).
- **`statuspage_unavailable` was declared but unreachable** — transport failures (network error, timeout, non-2xx, unparseable body) propagated as unclassified `InternalError`, and a non-conforming 200 response surfaced a raw JavaScript `TypeError` as the client-facing message. Every fetch failure in `cached-fetch.ts` now maps onto `ServiceUnavailable` with `data.reason: 'statuspage_unavailable'`, and the per-vendor `error` field on `devops_status_check`/`devops_watch_stack` never carries a raw runtime error message ([#32](https://github.com/cyanheads/devops-status-mcp-server/issues/32)).
