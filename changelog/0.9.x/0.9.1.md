# 0.9.1 — 2026-10-08

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.14** — what MCP clients of this server see:
  - Tool error results end with `request <id>` and carry `data.requestId` (`cyanheads/mcp-ts-core` 0.13.10); the ID is always server-generated, and a client's string JSON-RPC id is no longer adopted (`cyanheads/mcp-ts-core` 0.13.12).
  - Error `data` no longer carries server stack traces (`cyanheads/mcp-ts-core` 0.13.7), request context such as `operation` or `tenantId` (`cyanheads/mcp-ts-core` 0.13.8), or `rootCause` (`cyanheads/mcp-ts-core` 0.13.13).
  - Arguments are repaired before validation: an integer sent for a string field and a JSON-stringified object (`cyanheads/mcp-ts-core` 0.13.9); a numeric or boolean string for a number or boolean field, a lone string for an array, and `null` at an optional key (`cyanheads/mcp-ts-core` 0.13.14). `devops_get_incidents` with `limit: "3"` is now accepted.
  - Argument rejections name the field path (`cyanheads/mcp-ts-core` 0.13.9) and are capped in size (`cyanheads/mcp-ts-core` 0.13.14).
  - `ctx.log` notifications sent to the client honor `MCP_LOG_LEVEL` and mask sensitive fields (`cyanheads/mcp-ts-core` 0.13.11).
  - MCP SDK `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0: over HTTP, a 2026-07-28-protocol POST without `MCP-Protocol-Version` is refused `400`, and a JSON-RPC batch of more than 100 messages is refused (`cyanheads/mcp-ts-core` 0.13.9).
- **Recovery hints** — `devops_status_check`, `devops_watch_stack`, `devops_get_incidents`, `devops_check_certs`, and `devops_check_dns` no longer forward each declared hint by hand; the framework fills it from the tool's `errors[]` entry (`cyanheads/mcp-ts-core` 0.13.10). Callers see the same hints (verified for `vendor_not_found`, `invalid_domain`, `target_blocked`, `invalid_since`, `no_stack`) and `tools/list` is byte-identical to 0.9.0.
- **Docker** — dependencies install in a `deps` stage on `$BUILDPLATFORM` with a cross-arch install, so multi-arch builds no longer run Bun under emulation. Musl-only packages are pruned from the image, base images move to Bun 1.4.2, a `HEALTHCHECK` probes `/healthz`, and the image carries `org.opencontainers.image.version`. The unused `MCP_FORCE_CONSOLE_LOGGING` is removed.
- **`server.json`** — npm entries use `runtimeHint: "npx"` instead of `"bun"` and drop the `run start:stdio` / `run start:http` package arguments; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http`.
- **`.env.example`** documents the framework's newer env vars (request-state key, HTTP resumability, log rate limiting and failure payloads, OTLP per-signal endpoints) and the `127.0.0.1` HTTP host default.
- **`.gitignore` / `.dockerignore`** ignore all `.env*` files (`.env.example` stays tracked) and the registry token files; **`.mcpbignore`** excludes `docs/idea.md`, `logs/`, `.cache/`, and `tests/` from the bundle.
- **CodeQL workflow** analyzes each language under its own `/language:<language>` category.
- **`package.json`** — `packageManager` is `bun@1.4.2`, the `test` script is `vitest run`, and `files` excludes `dist/*.mcpb`. README Bun and MCP SDK badges follow.
- Synced `framework-skills/` and resynced `scripts/`, including the new `install-otel.ts` and `prune-musl-packages.ts`.
