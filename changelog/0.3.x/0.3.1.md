# 0.3.1 — 2026-07-02

## Added

- **Recovery hints on the wire** — `ctx.recoveryFor(reason)` is spread at all 9 `ctx.fail` sites across the 5 tool definitions, so `data.recovery.hint` (mirrored into `content[]`) now accompanies every declared error path: `invalid_domain`, `vendor_not_found`, `target_blocked`, `no_stack`. No reason, code, or message text changed ([#13](https://github.com/cyanheads/devops-status-mcp-server/issues/13)).

## Fixed

- **`devops_watch_stack` annotations** — now advertises `readOnlyHint: false, destructiveHint: false` (was `readOnlyHint: true`): providing `vendors` persists the stack list via `ctx.state.set`, and the only write is an upsert of the caller-named stack key. `idempotentHint: true` / `openWorldHint: true` unchanged ([#8](https://github.com/cyanheads/devops-status-mcp-server/issues/8)).
- **Cert/DNS timeout env vars wired in** — the `timeout_ms` input defaults on `devops_check_certs` / `devops_check_dns` are now lazy Zod defaults resolved at parse time from server config, so `DEVOPS_STATUS_CERT_TIMEOUT_MS` / `DEVOPS_STATUS_DNS_TIMEOUT_MS` (previously parsed but unused) set the effective default; an explicit caller-passed `timeout_ms` still wins. Field descriptions, README, and `.env.example` name the env vars ([#9](https://github.com/cyanheads/devops-status-mcp-server/issues/9)).
