# 0.8.0 — 2026-07-30

## Added

- **`maintenance` indicator** — `VendorResultSchema.indicator` and `StatuspageSummaryResponseSchema` gain a `maintenance` value alongside `none`/`minor`/`major`/`critical`, carried through `devops_status_check`, `devops_watch_stack`, and `devops_suggest_action`'s `vendor_indicator` input/echo. `summary.maintenance` is its own aggregate bucket, counted apart from `degraded` and `down`; `devops_watch_stack`'s `health` rollup gains a `maintenance` rung, ranked below every outage rung and below `unknown`, above `all_operational`. Only a Statuspage page reaches this state — the native adapters synthesize an indicator by ranking incident impacts and never produce it, which the new `StatuspageSeverityIndicator` type states directly ([#44](https://github.com/cyanheads/devops-status-mcp-server/issues/44)).
- **`devops_check_dns` `records_same_as_domain`** — each per-resolver entry in `resolver_results` gains this field, naming record types answered exactly as the domain-level `records` set. Those types are dropped from the resolver's own `records` object rather than repeated ([#41](https://github.com/cyanheads/devops-status-mcp-server/issues/41)).

## Changed

- **`devops_check_dns` `resolver_results[].records`** — no longer unconditionally carries every requested record type. A type answered identically to the domain-level set is elided and named in `records_same_as_domain` instead; `format()` states the agreement in words rather than rendering a bare status line ([#41](https://github.com/cyanheads/devops-status-mcp-server/issues/41)).
- **`renderVendorBlock()` degraded-component rendering** — leads with a count and a per-status breakdown, then lists every component on its own line grouped under its status; `under_maintenance` renders in its own group marked as a scheduled window rather than one more outage. The list stays uncapped in both tools ([#39](https://github.com/cyanheads/devops-status-mcp-server/issues/39)).
- **`devops_get_incidents` empty-result guidance** — an empty `filter: "all"` now states that the vendor currently publishes nothing at all and points at its status page, instead of recommending narrower filters that are empty by construction ([#43](https://github.com/cyanheads/devops-status-mcp-server/issues/43)).
- **README** — corrected the backend list: `gcp` (Google Cloud Service Health) is a native adapter, not out of the registry; Azure remains out because its feed is RSS with no severity or lifecycle field.

## Security

- **IPv6 SSRF range matching** (`src/utils/ssrf-guard.ts`) — replaced string-prefix matching with bitwise prefix-length matching over the parsed 128-bit address. String matching both under-blocked (`fe80::/10` link-local spans `fe80::`–`febf::`, but the `'fe80'` prefix left most of that span open, and `ff00::/8` multicast was unchecked entirely) and over-blocked (`'::1'` misclassified `::1234:5678`, IPv4-compatible IPv6, as loopback). An IPv4-mapped address is now classified by the IPv4 it embeds, matching both the dotted and all-hex encodings. Unparsable IPv6 text fails closed — blocked rather than assumed public ([#38](https://github.com/cyanheads/devops-status-mcp-server/issues/38)).
