# 0.5.2 — 2026-07-10

## Added

- **Incident-context tailoring in `devops_suggest_action`** — `affected_components` and `incident_summary` are matched (deterministic, category-scoped substring — no LLM call) against built-in rules; a matched subsystem section (CI/CD pipelines, DNS resolution, replication/failover, or login/sessions) is prepended ahead of the generic category playbook, and a detailed `devops_status_check` re-check of the affected vendor is added to `nextToolSuggestions`. The category playbook stays the fallback when nothing matches ([#21](https://github.com/cyanheads/devops-status-mcp-server/issues/21)).

## Fixed

- **`devops_suggest_action` vendor resolution** — the `vendor` input now resolves a display name (`Amazon Web Services`), not only a slug (`aws`), via a new layered `getBySlugOrName` lookup, so `vendor_category` populates and the pre-filled follow-up calls (e.g. `devops_get_incidents`) carry the canonical slug instead of the unresolved name. An ambiguous bare word (e.g. `cloud`) stays unresolved rather than matching an arbitrary registry entry ([#20](https://github.com/cyanheads/devops-status-mcp-server/issues/20)).
- **`incident_summary` truncation** — `diagnostics_summary.incident_snippet` now carries the full `incident_summary` instead of clipping it to the first 200 characters ([#21](https://github.com/cyanheads/devops-status-mcp-server/issues/21)).
