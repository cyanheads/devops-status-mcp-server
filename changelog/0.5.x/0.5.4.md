# 0.5.4 — 2026-07-11

## Changed

- **Empty-result guidance** — `devops_get_incidents` and `devops_list_vendors` now explain an empty result and name a concrete next step (a broader incident `filter` such as `"all"`; a category or cleared query for vendors), instead of rendering a bare header ([#17](https://github.com/cyanheads/devops-status-mcp-server/issues/17)).

## Fixed

- **`devops_get_incidents` history cap** — FireHydrant-backed vendors (Redis Cloud) exposed only the 50 newest incidents, silently dropping older history. The adapter now returns the full history and the tool windows it with a new `offset` input; a truncated result reports the true `totalCount` and names the next `offset` to fetch ([#22](https://github.com/cyanheads/devops-status-mcp-server/issues/22)).
