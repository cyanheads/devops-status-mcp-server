# 0.5.1 — 2026-07-10

## Added

- **Supply-chain install guard** — `bunfig.toml` sets `minimumReleaseAge` (a 3-day quarantine on newly published package versions, with `@cyanheads/mcp-ts-core` excluded so framework releases adopt same-day) and registers the Socket install scanner (`@socketsecurity/bun-security-scanner`) to screen packages for malware, typosquats, and CVEs before install.
- **`.github/SECURITY.md`** — security policy: private vulnerability reporting via the GitHub Security tab or casey@caseyjhand.com; fixes land on the latest release.
- **`.gitattributes`** — LF line-ending normalization, binary-asset markers, and `linguist-generated` on `bun.lock`, `CHANGELOG.md`, and `docs/tree.md`.

## Changed

- **Packaging** — `package.json` author normalized to `Casey Hand <casey@caseyjhand.com> (https://caseyjhand.com)`; `packageManager` pinned to `bun@1.3.14`.
- **`Dockerfile`** — base images pinned `oven/bun:1.3` → `oven/bun:1.3.14`; BuildKit cache mounts (`/root/.bun/install/cache`) added to the install layers; the build-stage install now runs `--ignore-scripts`.
- **Skill sync** — bundled skills and tooling refreshed to mcp-ts-core 0.10.14 (`devcheck` depcheck allowlist gains the Socket scanner; changelog `security`-flag guidance clarified to exclude dependency CVE bumps).

## Fixed

- **`devops_watch_stack` aggregate health** — errored vendors no longer roll up as `all_operational`. A fetch error now forces a non-green rollup via a new `unknown` health state, and `summary.unavailable` counts errored vendors so the buckets partition the stack (`operational + degraded + down + unavailable = total`) ([#15](https://github.com/cyanheads/devops-status-mcp-server/issues/15)).
- **`devops_watch_stack` stack persistence** — the vendor list is now saved only after target resolution and SSRF validation succeed, so a failed call no longer poisons the saved stack ([#16](https://github.com/cyanheads/devops-status-mcp-server/issues/16)).
