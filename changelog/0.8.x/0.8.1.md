# 0.8.1 — 2026-08-24

## Added

- **`cacheHint`** on `devops-status://vendors/{name}` and **`createApp({ cacheHints })`** for `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, and `server/discover` — a 1-hour public TTL, since the discovery surface and the compiled-in vendor registry are both constant for the life of the process.
- **`devops_watch_stack` `stack_name` charset validation** — `[a-zA-Z0-9_-]` segments joined by single `.`/`/` separators, 1-64 characters, matching the `ctx.state` key charset. A name outside it is rejected at the schema instead of surfacing as an unattributed storage error.

## Changed

- **`@cyanheads/mcp-ts-core` `^0.11.0` → `^0.12.3`** (SDK v2 migration). Tool inputs are strict at the root — an undeclared argument key is rejected by name instead of silently stripped; an input that must stay open needs an explicit `.passthrough()`/`.catchall()`. The advertised `outputSchema` now declares the error envelope. Advertised JSON Schema moves to 2020-12. Every HTTP endpoint serves protocol revision 2026-07-28 alongside the 2025 era. An unknown or disabled tool now rejects with JSON-RPC `-32602` instead of resolving an `isError` result. `ctx.elicit`/`ctx.progress` are removed; handlers use `ctx.requestInput`/`ctx.inputs`.
- `tsconfig.json`/`tsconfig.build.json` split — type-checking (`tsconfig.json`, includes `tests/**/*`) is now separate from the emit config (`tsconfig.build.json`, `src/**/*` only). Surfaced several `exactOptionalPropertyTypes` violations in test files, now fixed.
- Bun pins to `1.4.0` (Dockerfile build + `-slim` stages, `packageManager`); the Dockerfile's production `bun install` and OTEL `bun add` now pass `--omit=peer`.
- `MCP_SESSION_MODE` default documented as `auto` (resolves to `stateful`); `.env.example` and the README env table note the published container overrides it to `stateless`.
- `.github/SECURITY.md` — vulnerability-report contact moves to `security@caseyjhand.com`.
- Skills resynced to the framework's shipped versions across 26 files (`add-tool` 2.16→2.20, `api-context` 1.9→2.1, `api-telemetry` 1.2→1.7 notable); `changelog/template.md`, `scripts/lint-mcp.ts`, `scripts/lint-packaging.ts`, and `scripts/tree.ts` resynced from the framework template.

## Security

- **`ssrf-guard`** — IPv4 blocklist gains `192.88.99.0/24` (6to4 relay anycast), `198.18.0.0/15` (benchmarking), and `224.0.0.0/4` (multicast). IPv6 classification changes from an enumerated blocklist to exclusion from `2000::/3` (the only block allocated to global unicast), so an unlabeled or newly-reserved range is blocked rather than assumed public; `64:ff9b::/96` (NAT64) is classified by its embedded IPv4, the same treatment `::ffff:0:0/96` already got, so a DNS64-synthesized address for a public host isn't blocked wholesale. `localhost`, `metadata.google.internal`, and `metadata.internal` are now rejected by hostname before DNS resolution.
