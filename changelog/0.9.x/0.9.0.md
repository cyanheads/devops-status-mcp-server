# 0.9.0 — 2026-09-25

## Added

- **`since`** on `devops_get_incidents` ([#40](https://github.com/cyanheads/devops-status-mcp-server/issues/40)) — a `YYYY-MM-DD` start-date floor, up to 24 months back, with `filter: "all"` or `"resolved"`. On Statuspage vendors it also reads the page's quarterly `history.json` archive back to that date, past the 50-incident API ceiling; a missing or failed archive keeps the API result and says how far history reached in `notice`.
- **`invalid_since`** error reason for a `since` past 24 months or paired with `filter: "active"`/`"scheduled"`.
- **`source`** on every `devops_get_incidents` incident — `api`, or `history` for an archive record, which carries title, impact, start/end (UTC, to the minute), and the final update message only. An archive record with no end has status `unknown`; the API copy wins when both exist.
- **`azure` vendor and Azure status adapter** ([#42](https://github.com/cyanheads/devops-status-mcp-server/issues/42)) — reads Microsoft's keyless Azure status RSS feed. Each posted item is an open `minor` incident with its services and regions as affected components; an empty feed reads `none`. New `api_type` value `azure`; the registry grows to 52 vendors.

## Changed

- **Timestamp field descriptions** on `devops_get_incidents` and the status tools no longer claim UTC — the fields carry the offset the vendor published.
- **`akamai`** registry URL is now `https://www.akamaistatus.com`; `status.akamai.com` redirects there and drops the query string.
- **`StatuspagePage.time_zone`** is optional — several v2-compatible pages omit it.
- SSRF-guard rejections are recognized and stripped through one `ssrfRejectionMessage()` helper ([#51](https://github.com/cyanheads/devops-status-mcp-server/issues/51)); definition strings are single-line literals ([#52](https://github.com/cyanheads/devops-status-mcp-server/issues/52)), rendered text unchanged. `clearFetchCache()` is exported for test isolation; `.gitattributes` keeps recorded XML fixtures byte-exact.
- README and `docs/design.md` document the history archive, the Azure feed, and AWS resolved events.

## Fixed

- **AWS status-0 (`[RESOLVED]`) events** ([#50](https://github.com/cyanheads/devops-status-mcp-server/issues/50)) map to resolved incidents rated by the highest severity their log reached, and stay out of the indicator, degraded components, and active incidents. `filter: "resolved"` now returns those the feed still lists.
- **Slack notice-only active list** ([#55](https://github.com/cyanheads/devops-status-mcp-server/issues/55)) reads `none` instead of `minor`; the indicator is the worst listed item.
- **Empty `filter: "active"`** on `devops_get_incidents` ([#57](https://github.com/cyanheads/devops-status-mcp-server/issues/57)) suggests only filters that can return more, and none on a backend with no resolved history or maintenance windows.
