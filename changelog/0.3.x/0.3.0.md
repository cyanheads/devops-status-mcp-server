# 0.3.0 — 2026-07-02

## Added

- **`devops_suggest_action` `vendor_indicator` input** — optional `'none' | 'minor' | 'major' | 'critical'`; pass the `indicator` from a prior `devops_status_check` call and the playbook leads with severity-tailored urgency guidance. Echoed as `diagnostics_summary.vendor_indicator` (now typed to the same enum instead of the always-null `string | null`) ([#10](https://github.com/cyanheads/devops-status-mcp-server/issues/10)).

## Changed

### Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.10.10`
- `@biomejs/biome` `^2.5.0` → `^2.5.2`
- `@types/node` `^26.0.0` → `^26.1.0`

## Fixed

- **`devops_get_incidents` enrichment contract** — `truncated` / `shown` / `cap` are now optional. They are written only when the cap is actually hit, so the previously-required fields made every non-truncated result fail the effective-output parse (`expected boolean, received undefined`) ([#5](https://github.com/cyanheads/devops-status-mcp-server/issues/5)).
- **`durationMinutes()` inverted-timestamp guard** — returns `null` when `resolved_at` precedes `started_at` (Statuspage data is vendor-authored and inverted timestamps occur in the wild); `format()` omits the duration segment instead of rendering `? min` or a negative value ([#6](https://github.com/cyanheads/devops-status-mcp-server/issues/6)).
- **`devops_suggest_action` honors `DEVOPS_STATUS_DISABLE_ACTIVE_PROBES`** — when the probe tools are unregistered, `nextToolSuggestions` no longer names `devops_check_dns` / `devops_check_certs`, and playbook diagnostic lines render manual equivalents instead (`dig` against multiple resolvers, `openssl s_client`) ([#7](https://github.com/cyanheads/devops-status-mcp-server/issues/7)).

## Security

- **`bun audit` 9 → 0** — transitive re-resolve cleared all 9 advisories (2 high, 6 moderate, 1 low): `hono` 4.12.26 → 4.12.27 via `@cyanheads/mcp-ts-core` `^0.10.10` (5 advisories, including the high-severity CORS-reflects-any-Origin-with-credentials [GHSA-88fw-hqm2-52qc](https://github.com/advisories/GHSA-88fw-hqm2-52qc)); `vite` 8.0.14 → 8.1.3 (2 advisories, including the high-severity `server.fs.deny` bypass [GHSA-fx2h-pf6j-xcff](https://github.com/advisories/GHSA-fx2h-pf6j-xcff), and drops `esbuild` — the low advisory — from the tree entirely); `js-yaml` 3.14.2 → 3.15.0 (quadratic-complexity DoS in merge-key handling).
