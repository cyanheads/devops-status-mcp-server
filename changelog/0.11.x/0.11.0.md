# 0.11.0 — 2026-10-30

## Added

- **`devops-status-guide` agent skill** — gates and identifier chains for the `devops_*` tools, served as `skill://devops-status-guide/SKILL.md` through `createApp({ skills: 'skills' })` and shipped in the npm package, `.mcpb` bundle, and Docker image.
- **Atlassian product entries** ([#74](https://github.com/cyanheads/devops-status-mcp-server/issues/74)) — `jira`, `confluence`, `bitbucket`, `jira-service-management`, `atlassian-compass`, `atlassian-developer`, `trello`, `opsgenie`, `atlassian-statuspage`, and `atlassian-guard`; the registry grows to 63 vendors.
- **`product_slugs`** on the `atlassian` entry and the `devops-status://vendors/{name}` resource ([#74](https://github.com/cyanheads/devops-status-mcp-server/issues/74)) — the product entries to check; the status tools and `devops_get_incidents` name them in `notice`.
- **`component_offset`** on `devops_status_check` and **`next_component_offset`** on a vendor's component list ([#82](https://github.com/cyanheads/devops-status-mcp-server/issues/82)) — continue a list past `component_limit`.
- **`affected_locations`** on Google Cloud incidents in `devops_get_incidents`, and `match` reads location names and IDs ([#84](https://github.com/cyanheads/devops-status-mcp-server/issues/84)).

## Changed

- **Breaking — `scheduled_maintenances[].scheduled_until`** on `devops_status_check` / `devops_watch_stack` is `string | null`, null when the vendor's feed publishes no planned end; it was `""` ([#91](https://github.com/cyanheads/devops-status-mcp-server/issues/91)). Firehydrant and Status.io windows read "end not published" in `content[]`.
- **`summary`, `health`, and the heading icon** rate a vendor by the worse of its `indicator` and its worst open incident rated minor or worse ([#87](https://github.com/cyanheads/devops-status-mcp-server/issues/87)); `indicator` stays as the vendor published it.
- **`atlassian`** is named "Atlassian (cross-product incidents)": it reads the umbrella page, which publishes no components ([#74](https://github.com/cyanheads/devops-status-mcp-server/issues/74)).
- **`devops_get_incidents` `since`/`until`** compare a record's start: `scheduled_for`, else the earlier of `started_at` and `created_at` ([#77](https://github.com/cyanheads/devops-status-mcp-server/issues/77)).
- **`devops_get_incidents` `filter: "scheduled"`** lists completed windows on Firehydrant, newest start first ([#85](https://github.com/cyanheads/devops-status-mcp-server/issues/85)); the descriptions name which backends list them.
- **`devops_get_incidents` `notice`** gives the start date of a feed with no history archive when `since` is earlier, and an empty range there no longer says to widen it ([#88](https://github.com/cyanheads/devops-status-mcp-server/issues/88)).
- **Status.io (overall code 200) and Firehydrant (a started window)** read `maintenance` only while no open incident rates above `none`; an outage outranks a window ([#79](https://github.com/cyanheads/devops-status-mcp-server/issues/79)).
- **`devops_check_dns` and `devops_check_certs`** render record values, certificate names, headings, and deferred entries as code spans that read back exactly as written ([#75](https://github.com/cyanheads/devops-status-mcp-server/issues/75)).
- **`devops_check_dns`** no longer refuses a domain that resolves to a private address; resolver IPs keep the guard ([#89](https://github.com/cyanheads/devops-status-mcp-server/issues/89)). The `DEVOPS_STATUS_ALLOW_PRIVATE_TARGETS` description lists what it covers.
- **`devops_check_dns`** names only the address types that got NODATA in its "No … records found" flag ([#80](https://github.com/cyanheads/devops-status-mcp-server/issues/80)).
- **`devops_check_certs` `chain_depth`** descriptions state that it counts the chain the runtime assembled, not the certificates the server sent ([#86](https://github.com/cyanheads/devops-status-mcp-server/issues/86)).
- Bun 1.4.3 → 1.4.4 (`packageManager`, Dockerfile base images); synced `framework-skills/` and packaging lint.

## Fixed

- **Malformed upstream bodies** from AWS, Slack, Status.io, and Firehydrant fail as `statuspage_unavailable` and are never cached, rather than reading as all-clear ([#78](https://github.com/cyanheads/devops-status-mcp-server/issues/78)).

## Security

- A guard rejection for a hostname names no address or address class the caller did not supply; an IP-literal rejection still names the address the caller sent.
