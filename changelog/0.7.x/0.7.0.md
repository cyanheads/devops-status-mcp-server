# 0.7.0 — 2026-07-30

## Added

- **`gcp` adapter** (`src/services/status-adapters/gcp-adapter.ts`) — normalizes `https://status.cloud.google.com/incidents.json` (a bare incident array, no page envelope) into the Statuspage shapes. Severity maps `low` → `minor`, `medium` → `major`, `high`/`critical` → `critical`, with an unrecognized value degrading to `minor` rather than being dropped. Resolution is read from `end`, not from an update's own `status` field, so `filter: "resolved"` works for this backend. `uri` resolves to an absolute dashboard permalink on `shortlink` ([#37](https://github.com/cyanheads/devops-status-mcp-server/issues/37)).
- **Vendor registry** — new `gcp` entry (`Google Cloud`, `cloud` category), bringing the built-in registry to 51 vendors. `VendorApiType` and `backendHistory()` gain a `gcp` case: no incident ceiling (the feed is a rolling recent window bounded by age, not by a count), full resolved history, no scheduled-maintenance feed.

## Changed

- **`VendorEntry` / `ResolvedVendor`** — the non-`statusio` branch of both discriminated unions is now `Exclude<VendorApiType, 'statusio'>` instead of an explicit `'statuspage' | 'slack' | 'aws' | 'firehydrant'` list, so a new adapter's `api_type` no longer needs a second manual addition alongside `VendorApiType`.
- Tool descriptions, the `vendor-entry` resource's `api_type` field, server `instructions`, and the Codex plugin manifest's long description now name Google Cloud Service Health and the 51-vendor count.
