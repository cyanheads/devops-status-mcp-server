# 0.5.3 — 2026-07-11

## Fixed

- **`devops_check_certs` invalid_domain recovery** — the `domains` schema relaxed its per-element `.regex(...)` to `.min(1)`, so a protocol-prefixed value (`https://example.com`) now reaches the handler's `PROTOCOL_RE` check and returns the declared `invalid_domain` error with its recovery hint, instead of a raw Zod regex validation message ([#18](https://github.com/cyanheads/devops-status-mcp-server/issues/18)).
- **`devops_check_dns` blocked resolver IPs** — a private, loopback, or otherwise non-public resolver IP now returns the newly declared `target_blocked` error with a recovery hint; the handler wraps `checkDomains()` and translates the `SSRF_BLOCKED` throw, mirroring `devops_status_check`'s raw-URL guard, instead of failing with an unstructured error ([#19](https://github.com/cyanheads/devops-status-mcp-server/issues/19)).
