# 0.11.1 — 2026-10-31

## Added

- **`datadog` backend** ([#90](https://github.com/cyanheads/devops-status-mcp-server/issues/90)) — a native adapter reads each Datadog status page's `/config.json`, which `status.datadoghq.com` serves in place of the Statuspage API (403 before). Eight entries join `datadog`: `datadog-us3`, `datadog-us5`, `datadog-eu1`, `datadog-uk1`, `datadog-ap1`, `datadog-ap2`, `datadog-us1-fed`, `datadog-us2-fed`. The registry grows from 63 to 71 vendors, and `api_type` may now be `datadog`.
- **`affected_locations` on AWS incidents** in `devops_get_incidents` ([#95](https://github.com/cyanheads/devops-status-mcp-server/issues/95)) — the one region the event ARN names (`global` for a global service). `match: "me-south-1"` and `match: "bahrain"` select the same event.

## Changed

- **`devops_get_incidents` `match`** reads a term whose words are joined by punctuation (`eu-central-1`, `git-operations`) as one phrase: its words must appear together, in order, within one field ([#95](https://github.com/cyanheads/devops-status-mcp-server/issues/95)). Before, each word could come from anywhere, so `eu-central-1` matched the AWS `me-central-1` event. Terms separated by spaces still match across fields.
- **`datadog`** is named "Datadog US1"; it was "Datadog" ([#90](https://github.com/cyanheads/devops-status-mcp-server/issues/90)).
- **AWS global events** read "(Global)" in the incident title and component name where they read "(Unknown region)" ([#95](https://github.com/cyanheads/devops-status-mcp-server/issues/95)).
- **`devops_get_incidents` `notice`** names the date a feed starts for an `until` with no `since`, and says where a whole-history feed (`redis-cloud`, Datadog) begins when the range ends before it ([#94](https://github.com/cyanheads/devops-status-mcp-server/issues/94)).
- **`devops_get_incidents` update bodies** — obsolete formatting elements such as `<tt>` are stripped ([#90](https://github.com/cyanheads/devops-status-mcp-server/issues/90)).
- **`bun run verify:registry`** fails a Statuspage entry that publishes no components, except umbrella pages with `product_slugs` ([#96](https://github.com/cyanheads/devops-status-mcp-server/issues/96)).
- **`devops-status-guide` skill** `metadata.version` 1.0 → 1.1.

## Fixed

- **`devops_check_certs`** renders the host in the hostname-mismatch flag as a code span on the `**Flags:**` line of `content[]`; `structuredContent.flags` is unchanged ([#93](https://github.com/cyanheads/devops-status-mcp-server/issues/93)).
- **`devops_get_incidents` ceiling notice** names `since` and its 24-month reach on Atlassian Statuspage vendors, where it called older incidents unreachable ([#97](https://github.com/cyanheads/devops-status-mcp-server/issues/97)).
- **`devops_get_incidents` empty `filter: "all"` result** on a component-scoped entry at the 50-incident ceiling (`sendgrid`) no longer says the vendor lists nothing, and names the status page once ([#99](https://github.com/cyanheads/devops-status-mcp-server/issues/99)).
