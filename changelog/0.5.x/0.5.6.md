# 0.5.6 — 2026-07-30

## Added

- **`component_filter`** input on `devops_status_check` / `devops_watch_stack` — case-insensitive substring narrowing detailed-mode component lists before the cap ([#36](https://github.com/cyanheads/devops-status-mcp-server/issues/36)).
- **`component_limit`** input (default 50, max 500) bounding per-vendor detailed-mode component output; `all_components_total` on each vendor result discloses the pre-cap match count ([#36](https://github.com/cyanheads/devops-status-mcp-server/issues/36)).
- **`enrichment`** block (`truncated`/`shown`/`cap`/`totalCount`) on both tools, emitted once per batch when any vendor's component list was capped — `buildVendorResult()` has no `ctx`, so it returns component counts and the handler aggregates them across the fan-out ([#36](https://github.com/cyanheads/devops-status-mcp-server/issues/36)).
- **`omitted_vendors`** on `devops_watch_stack` — names entries left out of a saved stack because they could not be resolved or were SSRF-blocked ([#33](https://github.com/cyanheads/devops-status-mcp-server/issues/33)).

## Changed

- **`devops_status_check`** `summary` gained an `unavailable` bucket, mirroring `devops_watch_stack`, so `operational + degraded + down + unavailable = total` always holds; the rendered headline now discloses the count ([#23](https://github.com/cyanheads/devops-status-mcp-server/issues/23)).
- Vendor resolution and fetch logic shared by both tools consolidated into `prepareVendors()` and `fetchVendorResults()` in `devops-vendor-result.ts`, replacing duplicate per-tool loops.

## Fixed

- **`devops_status_check`** / **`devops_watch_stack`** no longer discard the entire batch when one vendor is unresolvable or SSRF-blocked — each failure becomes a per-vendor `error` row unless every vendor in the call fails, in which case the typed `vendor_not_found`/`target_blocked` error now names every failing entry instead of only the first ([#33](https://github.com/cyanheads/devops-status-mcp-server/issues/33)).
- **`devops_watch_stack`** now persists the resolvable subset of a stack instead of refusing to save when any entry fails; `omitted_vendors` reports what was left out ([#33](https://github.com/cyanheads/devops-status-mcp-server/issues/33)).
